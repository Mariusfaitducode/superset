# Desk: Marius reviews outcomes instead of driving conversations

Date: 2026-10-22. Fork `Mariusfaitducode/superset`, base `marius/main`.

## Why

The analysis of Marius's last three weeks (1–22 Oct, `~/Documents/agent-workflow-analysis/metrics.txt`) shows:

- His reply time is not the problem: median ~5 min in the day, stable up to 6+ agents running.
- The volume is: 48 → 57 → **114 messages per working day**, ~25 live sessions a day, up to 22 agents at once, 2.2 agents waiting on him on average (peak 10).
- 20 % of his messages were bare go-aheads ("commit et push", "tu peux post", "go"). 10+ "où en sommes-nous ?" to find out what agents were doing.
- Agents stop to ask questions or brainstorm (the n°1 friction this week), re-ask the same pending question several turns later, and he re-pastes the same context to several agents.

Goal: Marius stops being the driver of 25 conversations and becomes the reviewer of outcomes. Agents work until they have something to hand over; everything that needs him lands in **one queue** he clears in a few batches a day; what he has already allowed, agents do without asking; and he can see whether it works, week after week.

Success, measured by Insights: messages per working day under 50, bare go-aheads under 5 %, no "où en sommes-nous ?", agents waiting on him visible at a glance.

## The four parts

### 1. Agent reports (protocol)

Agents end a piece of work with a structured report instead of free text that Marius must read in each terminal.

- CLI: `superset report <kind> "<one-line summary>" [--details …] [--link <url>]… [--checks "<what ran, result>"] [--test "<what Marius should try>"] [--option "<label>"]… [--draft-file <path> --target <slack|github|notion|email>]`
- Kinds: `done` (deliverable ready for review), `decision` (needs a choice; options optional), `draft` (a text to send in Marius's name, waiting for his OK), `blocked` (needs access or an action only he can do), `progress` (optional, informative, never in the queue).
- Stored on the host like conversation to-dos (`~/.superset/state/agent-reports.json`), keyed by workspace + conversation (terminal), with status `open | answered | dismissed`, the answer, timestamps (created, answered) and createdBy.
- A new report of kind X from the same conversation supersedes its previous open one, so the same question is never asked twice.
- Host pushes changes to the app (same mechanism as to-dos and labels after #13).
- Skill `plugins/superset/skills/report/SKILL.md`: when to report, one report per hand-over, never ask in chat what can be a report.

### 2. Desk view (the queue)

A page in the app, reachable from the sidebar with a count badge, listing everything open that needs Marius, across all workspaces:

- Open reports (decision, draft, blocked, done), plus open to-dos that agents created for him.
- Grouped by kind, oldest first, each card: workspace, conversation title, summary, age, links (PR, CI), checks, test hint, options.
- Actions on a card, keyboard-first (j/k to move, Enter to open, number keys for options):
  - **Answer**: option button or free text. Sends the answer to that conversation's terminal (same path as `superset terminals send`) and marks the report answered.
  - **Approve draft**: sends "Approved, send exactly this text." (editable before sending).
  - **Done → Reviewed**: marks it answered, optional follow-up message.
  - **Open conversation**, **Dismiss**.
- The sidebar row of a conversation with an open report shows its kind (same visual language as the existing agent status dots).

### 3. Autonomy grants and pinned context

What Marius has already allowed should not cost a message.

- Per-workspace grants, set by Marius in the app (workspace settings or the Desk) and readable by agents: `push-own-branch`, `open-draft-pr`, `mark-pr-ready`, `reply-to-bots` (Greptile, CodeRabbit), `post-github-comment`, `slack-draft`. Default: none, except what `~/.claude/CLAUDE.md` already allows (local commits).
- Anything not granted that leaves the machine goes through a `draft` or `decision` report, never a chat question.
- `superset grants list` (agents), `superset grants set/unset` (Marius or the coordinator).
- Pinned context: workspace notes with kind `context` (a brief, a decision, a colleague's message) that every agent in that workspace receives at start, instead of Marius re-pasting them.
- `superset context` prints the block an agent should get at session start: open to-dos, labels, open reports, grants, pinned context. The SessionStart hook (`~/.claude/hooks/superset-context.sh`) calls it.
- v1 is advisory (instructions in context). Enforcement with a PreToolUse hook on `git push` / `gh pr comment` is a follow-up.

### 4. Insights view (is it working?)

A page that recomputes, on demand and incrementally, what `~/Documents/agent-workflow-analysis/*.py` computes from Claude Code transcripts (`~/.claude/projects/**/*.jsonl`), plus Desk data:

- Per week (and per day): Marius's messages per working day, median reply time (daytime), share of bare go-aheads, share of status questions ("où en sommes-nous", "continue"), share of corrections, live sessions, agents working at once (mean/peak), agents waiting on him.
- Per project (workspace / project), share of his messages.
- From the Desk: reports created per day, time a report waits for him (median), answered per batch.
- Small charts, French/English via Lingui like the rest. Parsing runs in the host off the main loop, caches offsets per file; never blocks the UI.
- Port the logic from the Python scripts (event classification: human typed vs tool results vs task notifications vs meta; duplicates across resumed sessions dropped by event key).
